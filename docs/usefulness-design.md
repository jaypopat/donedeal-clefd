# Useful comparisons from loaded search results

The first installed prototype rendered correctly but discarded useful comparison evidence whenever fewer than five matches were available. It also ignored explicit private-seller metadata and did not distinguish material variants.

## Evidence and price labels

Keep the five-match minimum, existing matching windows, stability checks, and 15% price boundaries. When a label cannot be supported but relevant listings exist, show those asking prices and links as a neutral comparison. Unconfirmed details must appear beside each affected reference and must never contribute to a qualitative price label.

Recover vehicle identity only from explicit page evidence. A title may corroborate a verified make/model search or state an unambiguous gearbox. A contradiction remains a contradiction. Joining a promoted card to structured listing data requires the same listing ID. Promotion alone supplies no vehicle facts.

Use a bounded registry for material variants observed in the captured searches. Separate recognised variants from unmarked titles. An unmarked title does not establish a base trim. Explain this limit beside comparisons. Do not claim that variants outside the registry have been separated.

This chooses Claude's compact evidence and reference-result design over the alternative that withholds all labels from unknown trims. The latter would remove ordinary-search labels without establishing whether a material variant is present. Explicitly separate known variants, disclose missing trim evidence, and retain conservative label gates.

## Warning correctness

Payment negation must refer to payment. Negated viewing does not negate a deposit demand. A service-history distance does not establish the current odometer reading. Redaction must preserve model, engine, and year facts while removing contact information and identifiers.

Long descriptions receive limited coverage whenever the original source exceeds the 4,000-codepoint budget. This conservative rule can report limited coverage even when redaction shortens the text enough to fit. It prevents a full-check claim when text may have been omitted. Coverage travels through messages, fingerprints, Worker results, and storage. Partial checks are not reused as full-detail enrichment.

## Verification

`bun scripts/coverage-report.ts` replays allowlisted snapshots through the real adapters and pricing code. Compare the same frozen files across revisions. Counts from different live searches are observations, not a before/after measurement.

Use the installed-extension browser workflow for consent, navigation, independent signals, provenance, pause, clear, keyboard interaction, and limited coverage. Use `scripts/smoke-warning-policy.ts` against a local Worker with remote Workers AI for the corrected warning examples. Synthetic provider tests do not establish real-world fraud accuracy.

No unseen listings are fetched. No minimum number of bargains or suspicious ads is a success criterion. Final acceptance requires independent Claude review and observed useful comparison links on ordinary live searches.
